# Cluster-Based Movie Recommendation API

FastAPI backend using the saved K-Means model from `train_model.py`.

## Project layout

```text
movie-recommender/
├── app/
│   └── main.py
├── artifacts/
│   └── movie_model.joblib
├── data/
│   └── ml-1m/
│       ├── ratings.dat
│       ├── movies.dat
│       └── users.dat
├── requirements.txt
└── train_model.py
```

Copy `app/main.py` and `requirements.txt` into the same project that contains your existing `train_model.py`.

## Setup

```bash
python -m venv .venv
# Windows:
.venv\Scripts\activate
# macOS/Linux:
source .venv/bin/activate

pip install -r requirements.txt
python train_model.py
uvicorn app.main:app --reload
```

Open http://127.0.0.1:8000/docs to try the API.

The backend expects the artifact generated by the training script at
`artifacts/movie_model.joblib`. You can override this with `MOVIE_MODEL_PATH`.
SQLite data is stored in `movie_recommender.db` by default; override with
`MOVIE_DB_PATH`.

## Main endpoints

| Method | Endpoint | Purpose |
|---|---|---|
| GET | `/health` | Check model/database status |
| GET | `/genres` | List supported genres |
| POST | `/users` | Create new user and assign cluster |
| GET | `/users/{user_id}` | Retrieve existing user |
| PUT | `/users/{user_id}` | Update preferences and recluster |
| POST | `/users/{user_id}/interactions` | Record view/like/dislike/watchlist/watched/rating |
| GET | `/users/{user_id}/recommendations?limit=10` | Recommend old catalogue movies |
| POST | `/movies` | Add a new movie and create targeted notifications |
| GET | `/movies?q=matrix` | Search movies saved in the app database |
| GET | `/users/{user_id}/notifications` | Retrieve in-app notifications |
| PATCH | `/notifications/{notification_id}` | Mark notification read/unread |
| GET | `/clusters` | Inspect cluster genre profiles |

## Example requests

### Create a new user

```json
{
  "user_id": "user-1001",
  "preferences": {
    "Action": 5,
    "Adventure": 4,
    "Sci-Fi": 5,
    "Comedy": 2,
    "Romance": 1
  }
}
```

### Record an interaction

```json
{
  "movie_id": "260",
  "event_type": "rating",
  "rating": 4.5
}
```

The `movie_id` above refers to a MovieLens movie ID. The backend imports the
catalogue movie into its local SQLite database when first encountered.

### Add a new movie

```json
{
  "movie_id": "new-001",
  "title": "Galactic Mission",
  "genres": ["Action", "Adventure", "Sci-Fi"],
  "description": "An original science-fiction adventure.",
  "min_cluster_score": 3.5,
  "max_clusters": 3
}
```

Notifications are stored in SQLite and can be displayed in the frontend.
This starter backend does not send actual email, SMS, or push notifications.

## Notes / limitations

- The backend assumes the artifact keys produced by the provided `train_model.py`.
- K-Means cluster IDs are arbitrary labels; cluster 0 is not inherently better
  than cluster 1.
- The new-movie targeting score is the average learned cluster rating for the
  movie's known genres, not a trained probability of liking the movie.
- Interactions are persisted. A submitted rating lightly updates the user's
  genre preferences and recalculates their cluster, but it does not retrain
  the K-Means model.
- This is a college-project starter. For deployment, add authentication,
  authorization, rate limiting, stronger validation, migrations, and an
  external notification provider.
